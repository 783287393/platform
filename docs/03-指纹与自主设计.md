# 03 稳定指纹与自主设计

## 1. 指纹算法（core/fingerprint.py）

```
fingerprint = sha256( pluginid | origin | method | path | sorted(param names) )[:16]
```

- **pluginid**：ZAP 规则号（如 10020）；
- **origin**：规范化后的 scheme://host:port；
- **method**：HTTP 方法（大写）；
- **path**：路径，去掉末尾斜杠；
- **param names**：排序后的参数名列表；
- **剔除易变参数**：timestamp、ts、nonce、sid、sessionid、token、_、rnd、rand。

## 2. 为什么不用描述文本做指纹

同一规则的描述文案在不同规则版本间可能变化，且多处实例描述相同；只按文本归并会漏合并。
指纹基于结构化字段，重复导入同一报告不会新建 Finding，只在 alerts 表追加本次出现记录。

## 3. 三个误合并 / 漏合并反例（tests/test_parser_dedup.py）

| 反例 | 输入 | 期望 |
| --- | --- | --- |
| 仅随机值不同 | `/login?ts=1&sid=a` 与 `/login?ts=2&sid=b` | 同一指纹，归并为一条 |
| 路径不同 | `/` 与 `/login` | 不同指纹，不合并 |
| 方法不同 | `GET /` 与 `POST /` | 不同指纹，不合并 |

## 4. 自主扩展清单

1. 白名单门禁：扫描前强制校验，越界目标拒绝并记录；
2. 稳定指纹与跨批次去重：重复导入不增殖 Finding，保留出现历史；
3. 漏洞状态工作流：7 种状态 + Verified 证据约束（Commit + 复扫批次）；
4. before/after 对比：新增 / 未变 / 已关闭 / 风险变化；
5. 脱敏导出：Token、Cookie、口令、JWT 正则脱敏后再导出 CSV/JSON。

## 5. 取舍说明

- 参数**值**不参与指纹（避免随机值导致重复创建），但参数**名**参与（避免不同参数被误合并）；
- 路径与方法不同绝不合并；CWE 以报告提供为准，缺失留空，不臆造；
- 描述/建议中的 HTML 一律净化为纯文本展示，不把扫描证据当作可信 HTML 执行。
