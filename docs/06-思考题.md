# 06 思考题

## 1. 扫描器告警在什么条件下才应成为 Confirmed 漏洞？

告警与页面可达性、业务影响一致，证据字段可复核，人工复核确认不是误报后，才置为
Confirmed。扫描器输出只是线索，不等于安全结论。

## 2. 风险等级应完全采用工具评级，还是结合资产、可达性和业务影响？

不能完全照搬工具评级。工具风险码基于常见利用场景，实际等级还要结合资产重要性、
可达性（仅回环 vs 对外暴露）、业务影响与现有缓解措施综合判断；平台保留工具风险码，
复核人可在理由中说明调整依据。

## 3. 稳定指纹如何在避免重复和避免错误合并之间取舍？

结构化字段（规则、origin、方法、路径、参数名）进指纹，易变随机值剔除；参数名不同、
路径不同、方法不同绝不合并。取舍边界由反例测试固定：仅随机值差异归并，资源不同则分开。

## 4. 为什么“复扫不再出现”仍可能不足以证明修复？

可能 after 扫描没有覆盖原页面、规则未加载、缓存或旧容器仍在运行。需要核对两轮 URL
覆盖、规则集与日志；覆盖不足时状态保持 Resolved，补手工验证后才置 Verified。

## 5. 安全报告中哪些信息需要脱敏，过度脱敏又会损害什么证据？

Token、Cookie、口令、会话标识、个人数据需要脱敏；但证据字段（响应头缺失情况、
URI、参数名、规则号）应保留，过度脱敏会让复核无法核对问题是否真实存在与是否修复。
