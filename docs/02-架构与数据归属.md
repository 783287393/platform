# 02 系统架构与数据归属

## 1. 架构

```
                ┌─────────────────────────────┐
                │        本人本地应用           │
                │  web/target_app.py :8000     │
                └──────────────┬──────────────┘
                               │ 已知 URL · 被动检查
                               ▼
                ┌─────────────────────────────┐
                │      ZAP 2.17.0（上游）       │
                │  before.json / after.json    │
                └──────────────┬──────────────┘
                               │ Traditional JSON
                               ▼
┌──────────────────────────────────────────────────────────┐
│              Streamlit 漏洞管理平台（本人实现）             │
│  门禁校验 → 解析 → 稳定指纹 → 去重归并 → 复核/指派 → 对比   │
└──────────────┬───────────────────────────────────────────┘
               ▼
        SQLite data/security.db
   batches / findings / alerts / reviews
```

## 2. 数据归属

| 数据 | 归属 | 说明 |
| --- | --- | --- |
| 告警规则判定 | ZAP 上游 | 规则库、风险码与证据提取属于 ZAP 既有能力，不计入本人成果 |
| 报告解析与指纹 | 本人实现 | `core/parser.py`、`core/fingerprint.py` |
| 漏洞主表与状态 | 本人实现 | `core/db.py`：findings/alerts/reviews/batches |
| 复核与处置 | 本人实现 | 负责人、状态、分支、Commit、复扫批次、理由 |
| 前后对比与图表 | 本人实现 | `core/compare.py` + Streamlit Dashboard |

## 3. 表结构

- **batches**：扫描批次（before/after），来源文件、目标、规则集、备注、文件哈希、导入时间；
- **findings**：漏洞主表，指纹唯一，记录规则、风险、CWE、首次/最近批次、状态、负责人、
  分支、Commit SHA、处置理由、复扫批次；
- **alerts**：每次扫描出现的实例（URI、方法、参数、证据、风险码），同一 Finding 跨批次留存；
- **reviews**：人工复核记录（判定、理由、证据备注、复核人、时间）。
